JANKOLOCK: 40 ORIGINAL HERO EXPANSION
Blender-authored art and proposed kit review package | 2026-10-23

WHAT TO OPEN
Each assets/<hero-id>/ folder contains:
  model.glb / model.blend       Clean flat-color rigid character assembly.
  portrait.png                 1024x1024 clean full-body illustration.
  model_fx.glb / model_fx.blend Same character with separate geometric effects.
  portrait_fx.png               Illustration showing the effect concept.
  effects.json                 Effect names, toggle subtree and limitations.
  palette.json                 Four semantic colors and material names.
  rig.json / manifest.rig.json  Named pivots, parents and motion guides.
  manifest.json                Actual geometry, bounds and file properties.
  kit.proposed.json             Proposed four-slot kit; NOT drop-in runtime code.

Six heroes also have model_cel.glb / model_cel.blend and portrait_cel.png.
Their hard shade bands are authored face/material regions, so they survive GLB
export. They are NOT dynamically responding toon shaders. Thick ink outlines
are Blender render effects; they are not embedded runtime outline geometry.
Selected cel variants intentionally extend the original four-color palette,
as requested later. Calendar has two-tone regions; the others use three tones.

EFFECTS AND ANIMATION
Load model_fx.glb (or a cel variant) to get the effects; model.glb is intentionally
clean. Toggle the named FX_ROOT subtree to show/hide the effect. Individual
pieces are named and can be moved by the caller. These are visible cosmetic
meshes, not particle emitters, programmed ability effects or gameplay logic.
They do not automatically damage, slow, heal, reflect or trigger timers.

Rigid joints have real descendant geometry. Use rig node names rather than
assuming node indices are identical in clean/FX/cel exports. Rotations and
translation limits are documented in the JSON. A range is an authoring guide,
NOT proof of collision-free motion across every combination. These characters
have no skeletal skinning, IK, baked gameplay animation or tested state machine.
The extra Calendar articulation preview demonstrates sample joint motion only.

COLOUR CUSTOMIZATION
The clean and FX versions use named paper, ink, manila and accent material slots.
The palette records sRGB hex values and linear GLB material factors. Preserve
sharing within a character, but clone material objects before independently
tinting multiple spawned instances in a game. A GLB cannot enforce a loader's
instance-cloning policy. For cel variants update all corresponding shade bands,
not only the base material. Calendar includes palette_cel.json; other cel
palettes/methods are recorded in effects.json.

COORDINATES AND SOURCE
GLBs use metres, Y-up, forward -Z, grounded character bodies. Blender sources
use Z-up and forward +Y. Decorative FX may extend beyond the character's bounds
and are not collision geometry. Caller owns root placement and gameplay hitboxes.
All meshes/materials are authored locally in Blender, with no remote textures,
commercial-game assets or brand marks. Sources and generation scripts are kept
alongside these exports. Body files remain separate from optional style variants.

PROPOSED KITS
kits/heroes.proposed.json contains the combined review catalog; per-hero copies
are beside models. The referenced game's exact schema and runtime source were
not supplied. The proposals therefore do not claim schema compatibility, engine
support for every composition, competitive balance or successful playtesting.
Some baseline requests (reflection, channel-specific immunity, cleansing,
absolute arena locking) exceed the permitted primitive vocabulary. Read each
kit's designNotes for the explicit simpler approximation instead of assuming
those unavailable mechanics were implemented. New accents were selected where
the brief omitted one and synchronized with the rendered character palette.

VALIDATION AND LIMITS
qa/ contains the parent's independent binary, illustration and kit checks.
evidence/ contains Blender reexport/reimport, rigid-motion and source checks.
Reports describe exactly what was tested; they do not certify game integration,
performance, collision tuning, usability at every camera scale or animation
quality. No existing Jankolock gameplay, camera, collision or UI code was changed.
