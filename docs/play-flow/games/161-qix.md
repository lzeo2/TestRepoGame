## Flow (from source)

1. Boot: scripts load, inline script calls `window.jixStart()` immediately (auto-start; the header comment mentions an old Start button, none exists now) and unhides `#restartBtn`.
2. Start/setup: `Game.run()` sets `then = timestamp()` then `frame()`.
3. Input/core loop: `Game.frame()` is a fixed-step loop: `setDelta()` clamps delta, then `while (delta > 0.01) update(0.01)`, then `render()`, then `requestAnimationFrame(frame)`. This is simulation stepping, not decorative animation. Input: `Key` map, arrows move `Player.movementVector` when `isOnGrid()` (x/y % 3 == 0), SHIFT raises speed from 100 to 300 (dash). `canMove` samples the offscreen canvas via `Graphics.sample` and refuses `Board.CELLS.path` cells.
4. Touch: `#dpad` buttons (`#pad-up/left/right/down`, shown at `pointer: coarse`) dispatch synthetic `KeyboardEvent`s through `fireKey()` - same code path as keyboard.
5. Score/progression: `#claim .sheet` percent via `Hud.setClaim`; `#timer #meter` width shrinks by `meterTick` each `updateTimer()` call from `Game.render`.
6. Lose: `Hud.onTimeOver()` fires when the meter hits 0 - it unhides `#restartBtn` and appends a `game-over` classed clone to `#claim`. No win state observed in inspected sources (claim% can reach 100 but no victory handler found).
7. Restart: `#restartBtn` click does `window.location.reload()`.

## Animation vs simulation

`Game.frame` performs real state stepping (`Player.update`) at 0.01 s fixed steps; `render()` redraws board/tail/player. HUD timer is decremented in render, so timer progress is tied to frames. Note `Hud.updateTimer` replaces itself with a no-op ("Fake stop") on expiry - intentional, and `onTimeOver` fires once.
