## Game1: Slipstream Borough

### Play loop

Start in a visibly rough Bricklet with no cash. Choose **Cut up** or **Highway sprint** in the garage. Drive a four-lane 3D fictional highway with responsive continuous steering, accelerator/brake, moving traffic, roadside buildings/overpasses, animated wheels and chase camera. Near misses score once per passed car; collisions deal bounded damage and slow the car with cooldown, never pay. Avoid traffic rather than a stationary lane-click demo.

Cut up: bank distance/near-miss earnings after escape or bust. Distance/near-misses raise heat; pursuing police cars appear, approach, and threaten actual collisions/containment. Escape at the sector endpoint; each successful sector increases the next sector's traffic/police difficulty, capped at level12. Loss retains prior ownership/upgrades and returns to garage, with a free ready starter and no fuel/repair softlock. No graphic violence or real-world driving instructions.

Racing is a distinct selectable mode **inside this game**, sharing cars/garage/road but not the police objective. Three visibly moving AI rivals have actual distance/speed and finish order; endpoint1200+150*level meters. Finish first to win/prize/progress; other places receive smaller earnings. No fake race timer/demo. Explicit race position/distance, countdown/readiness, finish result and retry/garage. Police mode may use the same distance limit for compact runs. Early starter opponents must be beatable without a cheat. Pause/hidden tab stops simulation; no offline chase progress.

Garage: inspect owned/locked cars, select/buy, upgrade engine/handling/armor0..5 with growing costs and actual speed/response/damage effects. Meaningful earned progression from starter to fleet. Cash capped1e9. Score/best, ownership, upgrades and difficulty saved under `slipstream-borough-v1`. Runs are in-memory; reload returns to garage with banked progress, never invents a payout. Start reserves a unique run ID; settlement only once. New profile/reset requires consent and preserves unrelated keys.

Secret owner-requested exact code is supplied privately in worker task. No cheat hint, visible cheat button, demo pregrant or code printed on start/help/cards. Listen to bounded alphabetic buffer only in garage and support the same code through a normal garage radio phrase input for mobile. Matching it sets persistent testMode, unlocks all16 cars and max test cash; purchases/upgrades never exhaust test money. Normal fresh game must NOT start cheated. Source inspection can discover a client-side code; no claim of cryptographic secrecy. Test evidence must label cheat-assisted progression, never count it as natural earning.

### Pure core ABI

`Games/Slipstream Borough/core.js` exports `freshProfile`, `validateProfile`, `startRun`, `stepRun`, `settleRun`, `buyCar`, `selectCar`, `upgradeCar`, `upgradeCost`, `applyCode`, `carStats`. Main's upgradeCost is the pre-purchase quote used by upgradeCar; invalid ownership/kind/max level rejects, test-mode quote0.

Profile `{version:1,cash,owned,selected,upgrades,level,best,nextRun,settledRun,testMode}`: unique owned IDs including bricklet, selected owned, upgrades map ONLY owned IDs with `{engine,handling,armor}` integers0..5 (canonical fill0 if absent), level0..12, bounded integer cash/best/counters, boolean testMode; validate plain descriptors/unknown keys before reading. `freshProfile()` cash0, starter only, nextRun1, settledRun0, testModefalse.

`startRun(profile,mode)` -> `{profile,run}`, mode `cutup|race`, reserve/increment nextRun. Run fields documented by engine worker, with stable minimum `{id,mode,status,distance,speed,x,hp,heat,score,earnings,traffic,police,rivals,elapsed,finishDistance,place}`. Entities have `{id,carId,x,distance,speed}`; forward relative render z=-(entity.distance-run.distance). Run.status `running|escaped|busted|finished`; seeded finite fixed-step-friendly copied simulation, no DOM/storage/RNG outside core. `stepRun(run,input,dt)` accepts steer-1..1/throttle0..1/brake0..1 and dt0..0.05, returns next run; retain selected car/spec fields in run so no profile argument. No frame-based economic rewards. `settleRun(profile,run)` -> profile rejects ongoing, wrong/unreserved/already settled IDs; updates earnings/best and level once, cap resources. No random reroll on settlement. `buyCar/profile select/upgrade` are copied atomic transactions, reject invalid/insufficient; testMode spends no money. `applyCode(profile,text)` returns copied profile (unchanged if unmatched). `carStats(profile,id=selected)` frozen effective specs, upgrades affect true mechanics. No test setters/debug hooks.

## Game2: Garage Borough

Begin with cash800, one bay, no inventory/staff. Buy used stock, restore/clean it, satisfy customers for profit/reputation, expand bays and hire mechanics. 3D garage/showroom contains actual owned inventory, selected detailed car on inspection stand, workers/bay upgrades and fictional signs. Orbit with pointer and keyboard; keyboard/touch can perform every management action. Staff produce real bounded restoration over active time. Inventory/customer/cost/condition feedback always shown.

Used acquisition `max(200,floor(car.price*0.5))`; starter condition45. Manual repair +25 condition, price `max(50,floor(acquisition*0.15))`. Customers demand a style/condition; matched sale `max(500,floor(acquisition*(1+condition/100)))`, reputation+1/sales+1 and remove exact inventory/customer once. Wholesale escape hatch offers at least50% acquisition when no customer matches. Customer expiry/active-time rent create pressure, not real-money monetization. Hire300+250*staff, staff0..3; bay expansion800*bays, bays1..4. Restoreone condition/3sec per staff appropriately capped. Rent every120 active seconds,150+50*staff; inability to pay closes business with clear loss/restart. No time-skip/negative-cash/infinite offline income.

Win milestone10 fulfilled sales -> “Garage of the day” result/Continue business; persisted achieved flag prevents repetitive victory rewards. No cheat in this second game unless later requested. Fictional cash/profit only. Save `garage-borough-v1`, strict inventory UIDs/style/condition/counters/timers, no origin-wide clear. Reset consent.

Pure ABI `core.js`: `freshBusiness`, `validateBusiness`, `tickBusiness`, `buyStock`, `restoreCar`, `sellCar`, `wholesaleCar`, `hireStaff`, `expandGarage`, `continueBusiness`. Canonical worker-documented fields version/cash/inventory/bays/staff/reputation/sales/elapsed/rentClock/customerClock/customers/nextUid/status/achieved. Copied atomic actions, timers capped, unique identities, no repeated payouts. `tickBusiness(state,dt)` dt0..0.05 and no changes while won/closed; statuses playing/won/closed. Buyer generator deterministically cycles styles, with available stock getting fair demand; max3 customers, bounded expiry. No waiting framework/backend.

Examples: “Buns motor, big dreams, lad.” “Indicators on holiday, cuh.” “Cuz, that bumper has seen paperwork.” Do not repeat all three every frame, disrupt controls, shame the player or copy famous dialogue. Exact-byte compare before scoped write; validate before serialization; <=128KiB; denied/invalid/quota/stale saves visibly disable automatic overwrite pending explicit reset/reload. No silent catch/success, arbitrary imported getters, external key/origin clear or shared save slot. Not a transaction/noncooperating/ABA guarantee. Small native shared CSS only, no UI framework.
