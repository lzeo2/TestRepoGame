Chromium **149.0.7827.196**, fresh isolated contexts, cache disabled, local
uncompressed HTTP, light theme. Desktop 1280x900 and touch/mobile-emulated 390x844.

This static total is not browser first-paint transfer: it includes unloaded
thumbnails but only one catalog copy. Chromium made two catalog requests
(bundle `Gu()` and shared authored `fetchGames()`), adding 37,847 body bytes with
cache disabled. The runner counts both, rather than silently deduplicating them.

- Bundle is `type="module"`; UX and concurrent SEO scripts are `defer`.
  No external parser-blocking script was observed. Deferred code can still occupy
  the main thread; defer is not proof of low CPU cost.
- The synchronous inline storage-denial shim precedes the bundle intentionally.
  It must protect unguarded bundled localStorage reads before app initialization.
- Two CSS links are render-blocking by design; inline CSS belongs to HTML weight.
  Fonts are local and all three use `font-display: swap`.
- `applyCardMetadata()` already sets `loading='lazy'` and `decoding='async'` before
  insertion. Native lazy loading fetches nearby offscreen images too; loaded
  counts greater than visible cards are not evidence of eager loading.
- Authored `openGamePlayer()` constructs the iframe only through the guarded
  launch path. Compiled `Wu()` renders its fallback iframe only with a selected
  game; initial selection is null. Both source and pre-launch observation support
  isolation. This audit does not test actual game loading or fullscreen input.

## Analytics exception and smallest recommendations

**Preserve approved gtag `G-ERN6R7YHJ5`; no lane3 removal, replacement or re-add.**
There is a source discrepancy for the orchestrator/lane5: the ID was absent from
current root/portal runtime sources. Tracked-reference search found it in
`docs/design_review.md`, not an active root script. Accordingly this run observed
zero external requests; it did not measure an enabled analytics download.
Do not describe that as measured analytics cost of zero on the deployed site.
The runner neither blocks nor changes analytics; external requests, failures,
endpoints, CDP completed-transfer bytes and potentially opaque Resource Timing
bytes are reported separately and excluded from the deterministic local gate.
Failed/pending or cross-origin timing-restricted resources cannot prove zero cost.

1. **Lane4: no weight edit needed.** Retain native lazy/async images and launch-only
   frame construction. Do not add eager image loops, game prefetches or thumbnail
   minification/conversion churn for this budget. If latency remains poor in an
   isolated run, profile `onMutations()` before changing it: it calls several
   filter/status helpers that repeatedly scan card visibility/layout. Only then
   consider one status update per reconciliation, with existing UI regressions.
   This is a profiling recommendation, not a proven CPU root cause.
2. **Lane5: no defer rewrite needed.** Keep the module/defer tags and storage-shim
   ordering. Keep OG/share art as metadata, not a preload or visible hero; the
   share PNG was not fetched in either browser window. Leave the approved gtag
   unchanged if present in the final integration; reconcile its current absence
   with the operator rather than silently adding/removing it for a green budget.
3. **Do not intercept global fetch to deduplicate the two catalog reads.** Their
   measured 37,847-byte overhead is small and the frozen bundle has no source.
   A shared-fetch rewrite or cache-policy change costs more compatibility risk
   than this passing budget warrants. Rerun the check after lane4/5 settle.
