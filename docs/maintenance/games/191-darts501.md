## Gameplay and controls

Start at 501, throw three darts per turn, finish exactly on zero with a double; inner bull 50 counts as a double. Below zero, leaving one or nondouble zero busts, restores turn-start score and ends that turn. Twenty turns is the failure limit. Click/tap a board location to throw. Focus the board for arrow aiming in eight-unit steps; Shift increases steps to twenty; Enter/Space throws. Random throw selects a point inside radius 180; power 0-100 increases scatter. New game resets during play; Play again hides the result overlay then resets. Sound on/off toggles optional synthesized tones. These are documented mechanics, not an externally verified regulation simulator.

## Audit findings

- **HIGH**, `index.html`, `throwDart()` scheduled `endTurn()` versus `reset()`: reset during a bust or third-dart delay leaves the old callback advancing the new match to turn two. Root fix: cancel tracked turn callbacks or gate them with a session generation. Recommended native repro: throw the third dart, immediately New game, wait one second; expected turn stays one.
- **MEDIUM**, `index.html`, `buildBoard()`/`throwDart()`: rendered double ring ends at radius 180, but scoring treats distance through 190 as doubles. A visually outside point in the 180-190 annulus scores. Minimal root fix: share the board radii constants between drawing/scoring, with a boundary regression.
- **MEDIUM**, `index.html`, `win()`/`lose()` and document overlay: result focus is not transferred or contained. Root fix: native modal semantics and restart focus; include reduced-motion paths for flyTrail/popups.
- Non-finding: bullseye explicitly sets multiplier two, so the old nondouble-bull checkout bug described in provenance is not present in this source.
