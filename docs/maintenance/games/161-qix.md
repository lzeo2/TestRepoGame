# Qix maintenance

## Identity and status

Registered ID **161**, category `arcade`, entry `Games/Qix/index.html`. Baseline `8c8a055`; seven files, 16,503 bytes. This local JIX source runs a drawing prototype, not the complete territory/enemy loop described by the catalog. Runtime code was not changed or browser-tested here.

## Implementation map

**Source review coverage:** all seven files read completely: HTML including CSS/input bridge, `styles/main.css`, and `scripts/{hud,input,graphics,player,game}.js`. No hidden engine/binaries remain in this folder's inventory.

Scripts load Hud, Key, Graphics, Player/Tail, then Board/Game. Global instances bind `#jix`, a 960 by 600 canvas, and the HTML calls `window.jixStart()` immediately. `Game.run/frame` uses requestAnimationFrame and 0.01-second simulation steps. `Board.draw` paints four static paths; `Graphics.line` scales coordinates by three. `Player.update` follows the pressed direction and records tail corners. `Player.draw` copies the canvas to an offscreen buffer used by `Graphics.sample` collision checks.

`Hud.updateTimer` reduces `#meter` every rendered frame; `onTimeOver` clones the claim sheet into an animated game-over panel. `Hud.setClaim` exists, but no game/player caller updates it. `Board.addPath` likewise has no gameplay caller.

## Gameplay and controls

The page starts automatically. Arrow keys set the movement vector; releasing a key does not explicitly zero the last direction, so motion continues until blocked. Holding Shift switches speed from 100 to 300. Touch d-pad supplies arrow keydown/keyup but no dash control. Restart is visible after startup and reloads the document.

There is no reviewed enemy actor, area-fill algorithm, trail closure scoring, target percentage or winning state. The only end feedback is timer expiry, and the movement loop continues afterward. The catalog's roaming spike spiral and territory claim mechanics are unsupported by this complete small-source review. This is a functionality finding, not permission to replace the prototype with an invented game.

## State and persistence

Globals `graphics/board/tail/player/hud/game` own runtime state. `Key._pressed` retains held keys; no blur-reset handler exists. Tail points accumulate in memory and are deep-copied with JSON each draw. No localStorage/save key/audio appears. `game.animationFrame` stores the scheduled frame ID but is never cancelled on time over. Repeated `jixStart()` calls would create additional loops; document reload is the current reset boundary.
