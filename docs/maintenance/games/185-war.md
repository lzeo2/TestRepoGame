## Implementation map

Source review coverage: complete `index.html` (CSS, shell, `Card`, `Game`, input/render helpers) and `LICENSE`. No unread engine/binary area exists. `Game.makeDeck()` creates 52 cards, `shuffleDeck()` uses shrinking-range Fisher-Yates, `dealCards()` gives both named players 26 cards. Normal rounds use `playRound()`, ties use `playWar()`, rank comparison uses `getInt()`/`findWinner()`. `pot`, `warCards`, `war`, `draw` and `players` form the engine state.

Shell functions `snapshotHands()`, `act()` and `flip()` separate visible reveals from cards already transferred. `renderCard()` builds text spans and accessible labels. `updateCounts()` reads surviving hands. `showEnd()` exposes `#endOverlay` and focuses `#playAgainBtn`; `startGame()` builds a new engine and focuses `#actionBtn`. ## Gameplay and controls

Start game deals a match. Flip compares top cards, winner takes the pot, and tied ranks switch the action to War. Each war lays one face-down card and compares another face-up card; repeated ties retain the accumulated pot. A side with fewer than two remaining cards is eliminated during war after surrendering what remains. Both sides exhausted yields Draw; otherwise last surviving player wins. Restart and Play again build fresh shuffled matches. There is no match duration limit and no strategic card choice.

Pointer/touch uses native buttons. Space flips only when the event target is `document.body`; focused buttons use native activation so one press does not double-flip. Enter likewise operates native buttons. No arrows, WASD, sound or automatic flipping are implemented. A restart may change deck order even though counts return to 26/26.

## State and persistence

`game`, `roundsWon`, `over` and `lastRevealed` belong to the shell. Hands are arrays popped from the end; won cards are inserted at the beginning. `snapshotHands()` uses offset two for the face-up war card. State is entirely in memory: no save keys, timers, pending callbacks or ongoing animation loops. Page reload returns to Start. `Game.deck` retains its created card list while dealt hands use a sliced array, so deck length is not the runtime remaining-card counter.

## Audit findings

- **LOW**, `index.html`, `act()`: terminal check occurs before `roundsWon` increments for the decisive non-tied round. Recommended repro: arrange one final opposing card, flip a winning round, compare the displayed rounds count. Impact: final summary undercounts victories by one. Minimal root fix: account for a completed winning round before the terminal return, while keeping repeated war ties uncounted.
- **MEDIUM**, `index.html`, `#endOverlay`/`showEnd()`: focus moves into the result overlay, but it has no dialog semantics, focus containment or background inertness. Keyboard users can tab to controls visually covered by the overlay. Root fix: make terminal dialog handling native or explicitly inert the background, restoring focus on restart.
- Non-finding: repeated war progression is button-driven, not recursive unbounded call-stack growth. No injection issue was found in `renderCard()`; ranks and suits use textContent and fixed lookup values.

## Safe iteration
